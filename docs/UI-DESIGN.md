# 插件清单同步 · 设置页设计方案 v2

> 目标：把「设置在哪、现在什么状态、下一步点哪个」三件事在一屏内说清；只做插件清单同步，其余范围预留但不干扰。
> 约束：DSH `settings.section` 槽位、仅 `--dsw-alias-*` 主题变量、只用浏览器模块表里的 React、文案走 Client 语言服务。

---

## 1. 现状为什么"乱"（问题诊断）

上一版的问题不是配色或间距，而是**一页里塞了四套并列的注意力焦点**：

| 问题 | 具体表现 |
|---|---|
| 配置藏起来了 | WebDAV 地址/用户名/密码在折叠区里，首次使用的人找不到入口；折叠按钮文案在「WebDAV 连接」与「收起」之间变化 |
| 状态噪声过大 | 首页 8 张等权卡片（本机数、远端数、冲突、备份、写入方式、上次检查、上次发布、上次应用），没有主次 |
| 差异区位置错误 | 差异表嵌在插件卡内部，展开后把卡片撑长；卡片里又套卡片（统计块带边框背景） |
| 两套"应用"模型 | 冲突行有「保留本机/采用 WebDAV」按钮，下方又有「应用所选变更」，勾选数与待决策数各说各话 |
| 空态/加载态不分 | 未配置、读取失败、加载中，都渲染成相近的提示行 |
| 崩溃即空白 | 一次改版删掉了 `connectionOpen` 声明，模板仍引用 → `ReferenceError` → 整个 slot 空白。页面必须"无数据也能画出骨架" |

设计要解决的是**层级**，不是装饰。

---

## 2. 设计原则

1. **配置永远可见**，但默认只占一行摘要；展开才出现表单。不使用需要被发现才能理解的折叠入口。
2. **一屏一个主动作**。当前状态决定哪个按钮是主按钮，其余按钮降级为次级/文字按钮。
3. **状态用一句话 + 至多 4 个数字**，其余沉到「详情」。
4. **差异是页面的一等区域**，不是卡片的附属物；无差异时该区域整块不占位。
5. **冲突必须一次只问一件事**，并在行内给出后果，不用全页级"应用"去混淆。
6. **任何状态下首屏都能渲染**（无配置、未检查、加载中、读取失败、崩溃前状态都要有骨架）。

## 3. 信息架构

单页、四段，从上到下固定顺序：

```
┌─ ① 连接条 Connection bar（常驻一行） ────────────────────────────┐
│  ● 已连接 app.koofr.net/…/temp    WebDAV 锁    [编辑连接]        │
└──────────────────────────────────────────────────────────────────┘
┌─ ② 插件清单 Plugin inventory（主区域） ──────────────────────────┐
│  插件清单                                        16 个插件        │
│  本机 16 · 远端 16 · 待处理 0 · 备份 0            [检查差异][发布] │
│  上次检查 15:12 · 上次发布 14:58（+2 / ~1）                        │
└──────────────────────────────────────────────────────────────────┘
┌─ ③ 差异与冲突 Differences（有内容才出现） ───────────────────────┐
│  待安装 2 · 待升级 1 · 待处理冲突 1        [全部应用][全部忽略]   │
│  …行…                                                             │
└──────────────────────────────────────────────────────────────────┘
┌─ ④ 预留范围 Planned scopes（最底部，折叠，仅一行） ──────────────┐
│  DSH 设置 · 模型配置 · MCP 配置 · Skill 配置（暂未开放）    ⌄       │
└──────────────────────────────────────────────────────────────────┘
```

### 为什么这样切

- ① 是"我在跟哪个服务器说话"，一行足够；表单是低频操作，展开即可，不需要单独页面。
- ② 是用户 90% 时间看的东西：数量、健康度、两个动作（检查 / 发布）。
- ③ 是决策区，独立成段才能承载表格与冲突，不再撑长 ②。
- ④ 只占一行，兑现"为未来预留"，又不抢注意力。

## 4. 线框（关键状态）

### 4.1 未配置（首次进入）

```
插件清单同步

┌────────────────────────────────────────────────────────────┐
│ ⚠ 还没有连接 WebDAV                                    │
│ 配置一个 HTTPS 目录后，可在这台机器与其他机器间同步插件清单。 │
│                                                            │
│ HTTPS 文件夹地址  [https://…/dir/                      ]   │
│ 用户名            [                                     ]   │
│ 密码              [                                     ]   │
│ 远端备份保留      [10]  份（0–50，当前清单不计入）          │
│ [保存并测试连接]                                           │
└────────────────────────────────────────────────────────────┘
```

规则：未配置时**直接展开表单**，而不是显示"打开连接设置"按钮（那正是上一版找不到配置的原因）。

### 4.2 已配置、未检查

```
● 已连接 app.koofr.net/dav/…/temp      [编辑]

插件清单                                            16 个插件
本机 16 · 远端 — · 待处理 — · 备份 —
还没有比对过。检查差异只读取远端，不会写入或安装。
                                   [检查差异]  [发布（主）]
```

### 4.3 有差异（主场景）

```
● 已连接 app.koofr.net/dav/…/temp      [编辑]

插件清单                                            16 个插件
本机 16 · 远端 18 · 待处理 3 · 备份 4
上次检查 15:12 · 上次发布 14:58（新增 2 / 更新 1）
                                   [重新检查]  [发布（主）]

待安装 2 · 待升级 1 · 冲突 1                        [全部应用]

┌ 选择 ┬ 插件 ───────────┬ 差异 ────┬ 本机 ─────────┬ WebDAV ──────┐
│  ☑   │ dsh-notes       │ 安装     │ —             │ 1.2.0         │
│  ☐   │ dsh-context     │ 升级     │ 0.87.0        │ 0.88.0        │
│  —   │ dsh-purge       │ 需手动   │ 未钉版本      │ —             │
└──────┴─────────────────┴──────────┴───────────────┴───────────────┘
                                 [应用所选 1 项]
```

### 4.4 冲突（单独区块，一次一问）

```
需要你决定的差异

dsh-context  本机 0.87.0 / WebDAV 0.89.0 / 上次同步 0.87.0
两边都改过。选择一侧后，另一侧会在它下次同步时处理。
   [保留本机版本，发布到 WebDAV]   [采用 WebDAV 版本]
```

规则：
- 两个按钮都写清"会发生什么"，不用「保留/采用」这种抽象词。
- 不可用的方向**禁用并给原因**（例如"本机版本较新，不能降级"），而不是直接消失。
- 冲突处理完立即刷新该行状态，不要求整页重新检查。

## 5. 组件规格

### 5.1 连接条

- 结构：状态点（成功/告警/未配置）+ 目标摘要（域名 + 末两级路径）+ 写入方式 + 文字按钮「编辑」。
- 展开后是一个 `<form>`，字段顺序：地址 → 用户名 → 密码 → 保留份数 →（自动安装开关，独立一行并说明后果）。
- 保存成功：连接条更新、状态区回到"未检查"，并提示"已保存，建议先检查差异"。
- 地址或用户名变化时：关闭自动安装、清空旧统计（不得沿用上一个目标的数字）。
- 密码：只显示"已保存/未保存"，留空即保留。

### 5.2 插件清单区

- 标题 + 插件总数（本机可移植插件数）。
- **指标行**：只放 4 个 —— 本机、远端、待处理、备份。等宽数字，无边框卡片。
- 状态句：上次检查时间 / 上次发布结果（新增 n、更新 n）。
- 动作：`检查差异`（次）与 `发布`（主）。主按钮文案固定，不随"同步时安装缺失插件"开关变化。
- 空态：未检查 → "还没有比对过"；已检查无差异 → "两边一致，无需处理"（绿色勾）；读取失败 → 错误句 + `重试`。

### 5.3 差异区

- 表头四项：选择、插件、差异类型、本机 / WebDAV（两列合并展示为"本机 → 远端"更省宽）。
- 默认勾选：仅"安装"；升级与启停默认不勾（沿用既有规则）。
- 不可处理行（需手动、本机较新、来源不同、未钉版本）不显示勾选框，右侧给原因短标签。
- 底部只保留一个动作：`应用所选 N 项`；数量为 0 时禁用。
- 冲突不在此表内，移到独立的冲突小节。

### 5.4 冲突区

- 每条冲突一张轻量卡片（或表格一行 + 操作列），含三列版本：本机 / WebDAV / 上次同步。
- 两个动作按钮互不默认聚焦；执行前用页面内确认条，不用 `window.confirm`。
- 结果就地更新，并把冲突数从指标行里减掉。

### 5.5 预留范围

- 一行文字 + 折叠三角：`DSH 设置 · 模型配置 · MCP 配置 · Skill 配置（暂未开放）`。
- 展开后每项一行：名称 + 一句话范围 + 「暂未开放」标记，无开关、无按钮。
- 不出现"当前支持/预留项目"两个并列标题，避免把未实现的东西抬到与主功能同级。

## 6. 状态与文案

| 状态 | 指标行 | 主按钮 | 说明句 |
|---|---|---|---|
| 未配置 | 不显示 | — | 展开表单（见 4.1） |
| 读取失败 | 不显示 | 重试 | "无法读取连接设置" |
| 已配置未检查 | 本机有值，远端 `—` | 发布（禁用） | "还没有比对过" |
| 检查中 | 保留旧值 + 行内进度 | 禁用 | "正在读取远端清单…" |
| 一致 | 四项齐全，待处理 0 | 发布 | "两边一致" |
| 有差异 | 待处理 > 0（强调色） | 发布 | "检查于 hh:mm" |
| 冲突 | 待处理含冲突（告警色） | 发布 | "有 N 项需要你决定" |
| 执行中 | 冻结勾选 | 禁用 | 逐项结果就地更新 |
| 部分失败 | 保留成功项结果 | 发布 | 失败项给错误码 + 重试入口 |

原则：**同一时刻只允许一个主动作**；执行中禁用写入类按钮，但保留滚动与查看。

## 7. 交互与 API 映射

| 用户动作 | Host 调用 | 预期返回 | 失败处理 |
|---|---|---|---|
| 保存连接 | `save` | 设置摘要（含 `passwordSet`） | 字段错误就地提示，不清空表单 |
| 测试连接 | `test` | `{mode}`（etag / lock） | 显示 HTTP/协议原因，保留已保存值 |
| 检查差异 | `preview` | `{id, items, overview}` | 保留上次结果并显示错误条 |
| 发布 | `sync` | `{id, items, added, updated, overview}` | 同上；`added=0, updated=0` 时提示"无变化" |
| 应用所选 | `apply {id, selected}` | `{outcomes, overview}` | 计划过期 → 提示"清单已变化，请重新检查"并清空选择 |
| 冲突选择 | `resolve {id, name, choice}` | 刷新后的计划 + `outcomes` | 过期 → 同上，移除该冲突行 |

硬规则：**冲突选择里会写远端的动作（保留本机）必须二次确认，且确认文案包含目标主机名**；普通发布/同步不再弹确认。

## 8. 视觉规范

- 区块之间用 `--dsw-alias-border-l1` 分隔线或 24px 间距，**不嵌套带边框的卡片**；主区域允许一个容器边框，内部不再套卡片。
- 数字用 `font-variant-numeric: tabular-nums`；告警用 `--dsw-alias-state-warn-primary`，错误用 `--dsw-alias-state-error-primary`，成功提示用 `--dsw-alias-state-success-primary`。
- 按钮层级：主（`--dsw-alias-brand-primary` 描边）、次（`border-l2`）、文字按钮（无边框）。同屏最多一个主按钮。
- 表格：横向可滚动容器可聚焦（`tabIndex=0` + `aria-label`），窄屏时"本机/远端"合并为一列 `0.87.0 → 0.89.0`。
- 表单：每个字段 label 在上，说明文字 12px 次要色；输入宽度自适应，最小 220px。
- 明暗主题：只引用 `--dsw-alias-*`；自测两种主题下的分隔线与告警色。

## 9. 可访问性

- 所有按钮 `type="button"`，主区域标题 `h2`，区块 `h3`。
- 状态变化放进 `role="status"`（`aria-live="polite"`）；错误用 `role="alert"`。
- 折叠区用 `<details>/<summary>` 或 `aria-expanded` + 受控区域；展开后焦点移到区块标题。
- 勾选框有 `aria-label`：`选择变更 · <插件> · <差异类型>`。
- 冲突的两个按钮都带 `title`，不可用方向 `disabled` 且 `title` 说明原因。

## 10. 实施顺序

1. **骨架优先**：先按 4.1–4.3 画出四段与三种空态，保证任何状态都能渲染（同步补 `npm run smoke`）。
2. **连接条**：摘要 + 展开表单 + 保存/测试 + 目标变更清理。
3. **指标行与动作区**：4 个数字、状态句、主/次按钮切换。
4. **差异区**：单表 + 默认勾选规则 + 应用所选。
5. **冲突区**：行内两选择 + 确认条 + 就地刷新。
6. **预留范围**：一行折叠。
7. 明暗主题、窄屏、键盘走查；浏览器控制台确认无 `slot entry crashed`。

验收清单（逐条勾）：
- [ ] 未配置进入即见表单，不需要先找按钮
- [ ] 任何状态下首屏非空白（含读取失败）
- [ ] 同屏只有一个主按钮
- [ ] 待处理数与实际可操作行数一致
- [ ] 冲突处理不依赖整页刷新
- [ ] 换 WebDAV 目标后旧统计清空
- [ ] 仅用主题变量、无 Harness Client 包引用
- [ ] `npm test`、`npm run smoke` 通过

## 11. 明确不做

- 不做多标签页（上一版三视图即失败原因之一）。
- 不做仪表盘式的 8 张统计卡。
- 不做每个范围的方向开关（插件清单同步目前只有"发布 + 应用"两个方向，等真的接入设置/模型/MCP/Skill 再引入方向配置）。
- 不引入 Harness UI 组件库，不写自定义弹窗（用页面内确认条）。
